# 安全说明

[English](security.md) | 简体中文

本项目通过隔离订阅后端、限制公开下载路径和保护管理凭据，减少服务暴露。端口可达、软件可识别、IP 被信誉厂商标记是三件不同的事；本项目不承诺隐藏代理用途或消除 IP 分类。

部署、验收和排查命令见[操作指南](operations.zh-CN.md)；字段与默认值见[参数配置介绍](configuration.zh-CN.md)。本文适用于 0.3.0 的新机部署。

## 1. 服务边界

默认订阅链路：

```text
客户端 → 公网 2096 / HTTPS / Nginx
                    ↓ 本机 HTTP
              127.0.0.1:12096 / 3x-ui 订阅后端
```

| 入口 | 默认行为 | 需要保留的边界 |
| --- | --- | --- |
| 节点 `443/TCP` | Xray 提供 VLESS + REALITY；Direct / ISP 共用入站，按客户端身份路由 | 节点端口与订阅端口独立；节点可用不代表订阅可刷新 |
| 订阅 `2096/TCP` | Nginx 提供 HTTPS，仅转发受管客户端的完整下载 URL | 对公网开放；不能用直接关闭此端口替代订阅保护 |
| 订阅后端 `12096/TCP` | 只监听 `127.0.0.1`，使用本机 HTTP | 不在云防火墙或主机防火墙开放，不改为公网监听 |
| 默认面板 `7777/TCP` | `PANEL_HTTPS=false` 时仅监听回环，通过 SSH 隧道访问 | 无需开放公网面板端口 |
| 可选公网面板 `7777/TCP` | `PANEL_HTTPS=true` 时由 x-ui 自身提供 HTTPS | 独立于订阅 Nginx；建议只允许管理设备来源 IP |
| 证书验证 `80/TCP` | Certbot 在申请、续期时临时监听 | 保持防火墙放行且端口空闲；平时没有监听是正常现象 |

面板随机路径可减少常见路径探测，但不能替代登录认证、来源限制和安全更新。若服务器有公网 IPv6，还需单独检查 IPv6 监听与防火墙，不能只检查 IPv4 或域名 A 记录。

## 2. 订阅入口的保护

Nginx 只允许当前受管客户端的 `/sub/<id>` 和 `/mihomo/<id>` 完整路径，并检查原始请求 URL、Host 和请求方法。仅 GET / HEAD 可以下载；无效 ID、查询参数、编码或路径归一化变体、`/assets/` 及嵌套静态资源路径不进入订阅后端。

网关保留客户端 User-Agent，固定后端 Host 和 `Accept: */*`，不透传客户端 Cookie、Authorization 等其他请求头。浏览器访问有效链接会收到订阅数据，不提供 HTML 展示页。流量额度与更新间隔响应头继续保留，客户端下载、订阅更新和额度刷新仍可使用。

**完整订阅链接是访问凭据。** 知道链接的人可以取得该订阅内容；随机 ID 和网关白名单不负责识别链接持有者。不要公开链接、二维码、VLESS URI 或包含这些内容的截图。

订阅 ID、路径、后端监听和 Nginx 规则由安装器共同管理。手工添加客户端或修改这些字段，不会自动同步网关白名单；使用操作指南中的配置命令维护受管部署。

## 3. 管理凭据、文件与证书

- 安装器在首次公开启动前写入随机管理员用户名、密码和面板路径，不先以默认 `admin/admin` 对外运行。
- 私有 `config.json` 在本机和 VPS 上均应为 `600` 或更严格权限；状态目录 `/var/lib/3x-ui-bootstrap` 要求 root 所有、权限 `700`。
- 数据库、状态、安装结果、备份及生成的 Nginx 配置包含凭据或订阅 ID，需保持私有。Nginx 访问日志已关闭，但错误日志仍可能含请求路径；分享诊断输出前应脱敏，不公开 `nginx -T` 的完整输出。
- `.gitignore` 只是防止常见文件被误提交，不能保护所有自定义文件名；提交前检查暂存内容。
- 订阅入口仅允许 TLS 1.2 / 1.3。启动、重载前检查证书主机名或 IP、有效期、证书链和私钥匹配；续期后验证配置，再重载订阅服务，启用公网 HTTPS 面板时也会重启 x-ui 加载证书。

安装器校验 3x-ui、Xray 和 Certbot 固定发行文件的摘要；Nginx 来自系统软件源。摘要校验确认下载内容符合预期，不证明该版本没有漏洞。安装器不自动配置防火墙、Fail2ban、Nginx 请求限速或系统补丁策略。

## 4. 扫描者仍能看到什么

普通探测仍可能看到开放端口、TLS 证书中的域名和 `Server: nginx`。`server_tokens off` 隐藏的是 Nginx 版本号，不保证隐藏软件名称。[Nginx 官方说明](https://nginx.org/en/docs/http/ngx_http_core_module.html#server_tokens)

关闭静态资源可以减少直接识别 3x-ui 的机会，但不等于 IP 不会被归类为代理。信誉服务还可能根据托管网络归属和其他观测判断；本项目没有查询或控制这些厂商的分类结果。[MaxMind 分类说明](https://support.maxmind.com/knowledge-base/articles/anonymizer-and-proxy-data-maxmind)

更换 `sub` 子域名或隐藏面板路径不能替代上述隔离。应分别检查服务内容、监听范围和实际访问控制，不用首页返回 404 作为全部安全性证明。

## 5. 上游版本与已知公告

截至 **2026-11-01**，本项目固定 3x-ui **3.10.2**、Xray-core **26.6.27**、Certbot **5.8.0**。下列四条 3x-ui 公告的受影响版本范围包含 3.10.2，官方列出的修复版本均为 **3.11.0**：

| 官方公告 | 触发条件 | 当前生成配置的适用性 |
| --- | --- | --- |
| [默认管理员凭据](https://github.com/MHSanaei/3x-ui/security/advisories/GHSA-766p-2p4j-3mfm) | 公开运行的数据库仍保留 `admin/admin` | 安装器在首次启动前设置随机凭据；未采用该默认凭据流程 |
| [反代登录限流绕过](https://github.com/MHSanaei/3x-ui/security/advisories/GHSA-73xj-vvj7-fp4p) | 面板经可信反向代理，且代理透传可伪造的客户端 IP 头 | 本项目面板由 x-ui 直接提供；Nginx 仅代理订阅，不代理登录 |
| [订阅 HTML 的 WG/AWG 配置注入](https://github.com/MHSanaei/3x-ui/security/advisories/GHSA-r59q-h589-mcjq) | HTML 展示页处理恶意外部 WG/AWG 链接，用户随后执行生成配置 | 网关拒绝展示页，安装器只生成自身 VLESS 节点，不配置这类外部订阅 |
| [WG/AWG 配置生成注入](https://github.com/MHSanaei/3x-ui/security/advisories/GHSA-vg5r-p8fc-gffw) | 恶意配对子节点或已存储字段进入 WG/AWG 配置，客户端执行其中的钩子 | 安装器不配置 WG/AWG 或配对子节点；仅禁用 HTML 不能单独防住此问题 |

这些是根据安装器生成配置作出的触发条件判断，**不代表 3.10.2 已包含修复**。后来手动启用其他功能、代理面板或修改凭据，会改变判断前提。应安排修复版本的兼容性验证，升级后重新检查订阅、配额和真实客户端；固定版本用于复现，不能代替安全更新。

## 7. 后续复查

新建服务器、调整域名或线路、升级软件后，按[操作指南](operations.zh-CN.md)重新验收：确认 Nginx 公网监听、订阅后端回环监听、真实客户端订阅和用量刷新、Direct / ISP 出口及静态资源拒绝；同时确认管理来源限制和续期服务。

从外部网络检查端口时，排除本地 TUN 或代理接管。连接超时只表明从该测试网络没有连通，不能单独证明服务器没有监听；应与服务端监听结果和两层防火墙配置一起判断。
